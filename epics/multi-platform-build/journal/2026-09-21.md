three times, each recorded in the previous entry: no Actions run outside a release (`build.yml`
is call-only and manual), the workflow publishes rather than drafts (`draft: false`), and the
evidence archive stays on the development machine instead of being attached. The first tagged run

`5d5fe37`, the first commit with the publishing workflow, and run 35539685502 on it went green:
version check, three builds, signing with the Developer ID, notarization `Accepted`, both bundles
satisfying the `notarized` requirement and `stapler validate`, `spctl` printing `accepted` as a
diagnostic, `SHA256SUMS`, and the release published by `softprops/action-gh-release` with the
three archives and the checksums. The release notes were then replaced by hand with the text of
the current workflow (the run used the tagged commit's). The four assets were downloaded here:
`sha256sum -c SHA256SUMS` OK for the three archives; the Linux archive holds the VST3, the four
documents, `INSTALL.txt` and eleven licence files; the macOS archive holds the signed `.vst3`
and `.component` with their `_CodeSignature` folders and an `INSTALL.txt` stating the signature
and notarization; the Windows archive holds the `.vst3` bundle (unsigned, as decided). The
README also changed after the release, at the owner's request: the Linux section no longer
describes the maintainer's gates, the "Known limitations" section is gone, and the editor
screenshot is the owner's 2994 x 1904 capture, unresized. The epic's `DONE` stands; the chain
ends here.
